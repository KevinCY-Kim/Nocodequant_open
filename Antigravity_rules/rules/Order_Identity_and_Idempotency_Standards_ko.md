# [V27.0] 주문 식별자 및 멱등성 표준 (Order Identity & Idempotency Standards)

## 1. 목적 (Purpose)
NoCodeQuant의 모든 거래 이벤트는 **단일 진실 공급원(SSoT)**을 가져야 하며, 중복 주문, 누락된 체결, 혹은 잘못된 데이터 수렴으로 인한 자본 손실 가능성을 원천 차단한다. 본 문서는 시스템 전반의 '식별자 생성 및 멱등성 보장'에 대한 절대적인 법규를 정의한다.

## 2. SSoT 식별자 위계표 (Hierarchy)

시스템은 다음의 우선순위에 따라 거래의 진실성을 판단한다.

1.  **`order_id` (FID 9203)**: 최상위 식별자. 원주문번호로서 전체 거래 생명주기(진입~청산)의 앵커 역할을 수행한다.
2.  **`fill_id` (체결 식별자)**: 부분 체결 단위의 고유성을 보장한다. (공식: `{base_id}_{unfilled_qty}`)
3.  **`gtid` / `stable_gtid`**: 전략적 세션 및 DB 영속성 관리를 위한 키.

## 3. 결정적 생성 공식 (Deterministic Formulas)

모든 모듈은 다음 공식에 따라 식별자를 생성해야 하며, 임의의 가공을 금지한다.

### 3.1 `fill_id` 생성 (Idempotency Guard)
부분 체결 시 체결번호(FID 912)가 재사용되는 브로커 환경에 대응하기 위해 다음 공식을 강제한다.
- **공식**: `fill_id = sanitize_order_id(base_id) + "_" + str(unfilled_qty)`
- **`base_id` 우선순위**: 
    1. `FID 912` (체결번호)
    2. `FID 9203` (주문번호)
    3. `FID 909` (원주문번호)

### 3.2 UNKNOWN 경로 수렴 (`stable_gtid`)
시그널 없이 유입된 수동/예외 거래의 경우에도 주문번호를 기반으로 결정적으로 수렴시킨다.
- **공식**: `stable_gtid = "UNKNOWN-{code}-{order_id}"`
- **목적**: 동일 주문번호(9203)로 들어오는 모든 파편화된 체결을 단 하나의 전략 세션으로 묶어 PnL 오염을 방지한다.

## 4. 정화(Sanitization) 블랙리스트 [V27.0]

`sanitize_order_id()` 함수는 다음의 '가짜 식별자'를 제거하여 빈 문자열(`""`)로 반환해야 한다.
- **실제 필터링 대상 (SSoT)**: `""`, `"JJ"`, `"None"`
- **향후 확장 규격 (상위 레이어 보조 처리)**: `"0"`, `"000000"`, `"NoneType"`
- **원칙**: 오염된 식별자가 유입될 경우, 시스템은 유효한 상위 식별자(9203)를 찾거나 최후의 수단으로 `UNKNOWN` 세션을 생성하여 고립시킨다.

## 5. UI 및 포렌식 하드닝 (UI/Forensic Hardening)

- **식별자 우선순위**: 전략성과보드의 "주문/식별자" 컬럼은 `order_id`를 최우선으로 표시한다.
- **포렌식 툴팁 (Forensic ToolTip)**: 모든 식별자 셀은 마우스 오버 시 전체 `GTID`와 원본 `order_id`를 동시에 노출해야 한다.
- **수량 투명성**: 체결 수량(Quantity) 컬럼을 식별자 옆에 배치하여 부분 체결의 규모를 즉각 파악 가능하게 한다.

## 6. AI 작업 시 준수 의무

1.  **동결 영역 (Frozen Area)**: `sanitize_order_id` 로직 및 `OrderManager`의 `acc_key` 생성 로직은 수석 아키텍트의 명시적 승인 없이 AI가 임의로 수정할 수 없다.
2.  **위반 시 조치**: 본 문서에 명시된 식별자 규칙을 우회하여 중복 기록이나 데이터 누락을 초래할 경우, 해당 AI 세션은 즉시 중단 및 롤백 대상으로 분류된다.
