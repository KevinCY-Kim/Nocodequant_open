  * 즉, 웜업 가드가 래칫을 무력화시켰다는 가설은 부분 오류였으며, **평가 주기의 시간적 지연**이 누수의 근본 원인입니다.

### 2. MME 총자산 이중 계산 (Double Counting) 결함
* **발생 시점**: 14:04 원익IPS 체결 직후
* **상황**: 원익IPS 매수 주문 체결(420만 원 소모) ➔ 키움 API 추정예수금 갱신 지연(1~2초) ➔ 이어서 스피어 매수 신호 계산.
* **오류 메커니즘**:
  * `Total Asset = 예수금 (미반영 1,701만) + 주식 평가액 (원익IPS 420만 가산) = 2,121만 원`으로 중복 계산됨.
  * 이로 인해 스피어 매수 금액(530만 원)이 원래 의도했던 예수금의 25% 비율을 초과한 31.2%로 과량 발주됨.
  * **해결책**: 체결 발생 시 API 갱신에 의존하지 않고, 로컬에서 매수 금액만큼 예수금을 즉시 차감(체결 기반 로컬 차감식)하거나, 15% 포지션 집중 제한 룰(Concentration Cap)을 복원하여 안전장치를 상시 가동해야 합니다.
