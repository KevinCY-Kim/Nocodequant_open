## ✅ 작업 내용

### 1. Adaptive Surveillance OS 및 멀티 탭 시스템 구축
- **개요**: 기존 `HOT(HEAT)` 탭 중심의 단일 감시 체계를 `PRE_HEAT`(돌파예보) 및 `REVERSE`(구조전환)로 확장하여 시장의 다양한 국면을 동시에 포착하도록 개선.
- **UI 구현**: `RankingWidget`의 탭 이름과 배열 순서를 직관적으로 개편 (추세 → 돌파 → 역추세 → 거래대금 → 급등 → 가속). 시각적 혼선을 줄이기 위해 이모지를 제거하고, 전략별 아이덴티티를 살린 전용 색상 테마(오렌지/퍼플)와 전용 컬럼 라벨(점화지수/전환지수)을 적용.
- **데이터 파이프라인**: 30초 주기 TR 데이터 수신 시, 하나의 데이터셋에서 가중치만 달리하여 5개 탭의 랭킹을 동시 산출하도록 최적화. UI 렌더링 병목을 방지하기 위해 탭별 업데이트 시점에 미세한 시차(staggered update)를 부여.

### 2. 시장 구조 기반 Feature Engineering (8종)
- **돌파예보(PRE_HEAT) 지표**:
    - **거래량 가속도(EMA)**: 단순 거래량 증가를 넘어 '증가율의 증가'를 포착하여 초기 점화 순간 탐지.
    - **VWAP 회복력**: 가격 이탈 후 빠르게 기준선을 복귀하는 탄성 측정 (Shakeout 판별).
    - **저점 상승 패턴(Higher Lows)**: 매수세가 바닥을 밀어올리는 구조적 지지력 확인.
    - **에너지 유지력**: 초기 유입 후 5~15분간 에너지가 증발하지 않고 유지되는지 검증.
- **구조전환(REVERSE) 지표 (V24.7 정밀타격 패치)**:
    - **Falling Knife Guard (신저가 차단)**: 최근 30스냅(≈3봉, 15분) 내 신저가 갱신 중인 종목 즉각 제외 (가짜 바닥 방지).
    - **Defense 가격 지지**: 하락 진동폭 감소뿐만 아니라, 후반부 저점이 전반부 저점을 깨지 않는 '구조적 방어' 확인.
    - **Volume Bias (매수 우위)**: 투매(음봉) 거래량을 자금 유입으로 착각하는 문제 해결. 양봉 윈도우의 '받아먹는' 거래량 비중 측정.
    - **Reclaim & Hold (시간 축 점수)**: 세션 평균가 재돌파 후 유지 시간(1봉/2봉/3봉+)을 점수화하여 '돌파 후 유지력' 검증.
    - **V-Shape Penalty (급반등 감점)**: 바닥 체류/매물 소화 없는 급하게 튀어오르는 세력 털기 패턴(Dead Cat) 감점.

### 3. 전략-탭 Attribution (기여도 추적) 시스템 V24.7 고도화
- **목적**: "어떤 탭에서 선별된 종목이 실제 매매로 이어졌는가"를 데이터로 증명하고, 최초 발굴 시점의 가치(Alpha Source)를 보존하기 위함.
- **핵심 로직**:
    - **초기/현재 분리 (Initial vs Current)**: 종목이 `PRE_HEAT`에서 발견되어 `HOT`으로 승격되더라도, 최초 발견 탭(`initial_source_tab`)을 절대 덮어쓰지 않고 보존하여 '발굴의 가치'를 추적.
    - **정밀 메타데이터**: 발굴 당시의 랭킹 점수(`source_score`)와 순위(`source_rank`)를 함께 기록하여 '탭 내 상위권 종목'의 성과를 별도 분석 가능하게 함.
    - **데이터 무손실 전파**: `RankingManager` → `ExecutionManager` → `OrderManager` → `PersistenceManager`로 이어지는 전 생명주기 동안 6가지 상세 속성 전파.
- **DB 및 UI 구현**:
    - **이중 포맷 저장**: 분석 효율성을 위해 탭 정보(문자열 TEXT)와 고유 ID(INTEGER)를 동시 저장하도록 DB 스키마 확장 및 마이그레이션 진행.
    - **상태 관리 및 메타데이터 보존 버그 픽스**: 매도(청산) 시점의 `TradeEvent` 생성 과정에서 `RankingManager`의 순위 밖으로 밀려난 종목들이 `UNKNOWN`으로 초기화되는 치명적 버그 수정.
        - `StateManager`의 `get_position_meta`에서 진입 시점의 `initial_source_tab` 등 6가지 속성을 명시적으로 반환하도록 패치하여 재시작 이후에도 매수 시점의 출처 데이터가 보존되도록 함.
        - `OrderManager`의 `on_fill_event`에서, `SELL` 신호에 딸려온 빈 메타데이터(`UNKNOWN`)가 보존된 기존 `pos_meta`를 덮어쓰지 못하도록 안전장치(Safe Merge) 구현.
    - **UI 렌더링 툴팁**: 거래 로그의 '감시탭' 필드 마우스 오버 시 최초 발견 및 종결 시점의 탭, 전시 점수 및 순위가 표시되는 분석용 툴팁 구현.
- **결과**: "PRE_HEAT 1~3위권에서 발굴된 종목의 실제 승률"과 같이 고차원적인 전략 통제 및 자금 배분 최적화 기반 마련.

### 4. REVERSE 감시망 - 실행 엔진 동기화 (Alignment)
- **배경**: 감시망(Ranking)은 '낙폭과대'를 물어오고 실행망(Engine)은 '안정화'를 요구하여 발생하는 0회 매매(Mismatch) 문제 해결.
- **5분봉 캘리브레이션**: 실시간 틱 데이터(`_quote_snapshots`)를 5분봉 타임프레임(1봉≈10스냅)에 맞게 재정의하여 감시와 전략의 시계열 일관성 확보.
- **철학의 전환**: "바닥 같아 보이는 종목" 찾기에서 "이미 첫 구조 회복 행동이 나온 종목" 찾기로 랭킹 로직 전면 개편.

### 5. 검증 및 안정화
- **임포트 검증**: `RankingManager` 내 신규 Feature 함수(`_is_falling_knife`, `_calc_volume_bias` 등)의 정상 로드 및 구문 오류 없음 확인.
- **런타임 테스트**: 실제 앱 기동 시 새로운 탭들이 정상 표시되고, 데이터 파이프라인 충돌 없이 백그라운드 연산이 수행됨을 확인.
- **리소스 체크**: 추가적인 키움 API TR 요청 발생 없이 멀티 탭 감시가 이루어짐을 보장.

### 6. 엔진 진입 임계값 하드닝 및 기술 부채 제거
- **SSoT 연동**: `_engine_entry.py` 내부에 존재하던 하드코딩된 임계값(TREND=58 등)을 모두 제거하고, `config_engine.py`의 `EngineDefaults`를 직접 참조하는 동적 Fallback 구조로 개편.
- **초기화 무결성**: `CompositionRoot`에서 `ACTIVE_CONFIG`가 엔진 가동 전 완전히 로드되도록 보장하여, 시스템 초기 시점의 오작동 가능성 차단.

### 7. 급등(GAIN) 탭 역할 재정의 및 정밀 타격 (V24.8)
- **정체성 확립**: "구조"를 보는 `PRE_HEAT`과 달리, 오직 **"순간적인 수급의 폭력성"**에만 집중하도록 로직 개편.
- **수급 증폭기 적용**: 실시간 수급 급증(`rt_surge`)과 거래량 가속도(`ema_accel`)를 스코어링에 직접 반영. 단, 노이즈 방지를 위해 멀티플라이어 상한(Cap)을 적용하여 찌라시 등에 의한 오염 차단.
- **Change Damping (12% 룰)**: 이미 12% 이상 상승한 종목은 '급등'의 초동 단계를 지났다고 판단하여 점수를 감산(0.7x). 이를 통해 "이미 달린 놈"이 아닌 "이제 막 살아나는 놈"이 상위에 노출되도록 유도.
- **유동성 가드(Run-Rate Gate) 도입**: 
    - 일거래대금 **150억 원 페이스** 미달 종목 차단 (호가창 장난에 의한 가짜 급등 제거).
    - 단, 수급이 매우 강한 경우 컷오프를 최대 50%(75억)까지 자동 완화해주는 다이내믹 게이트 적용.
    - 저유동성 종목의 분모 왜곡을 막기 위한 `effective_surge` 캡 적용으로 신뢰도 확보.

## 💡 특이사항 및 향후 과제
- **설명 가능한 시스템(Explainable OS)**: 단순 수치 threshold가 아닌, "왜 이 종목이 돌파인가?"를 구조적으로 설명할 수 있는 지표들로 채워짐에 따라 전략의 신뢰도 향상.
- **동적 슬롯 할당**: 향후 실시간 감시 슬롯(100개 제한)을 각 탭의 활성도에 따라 동적으로 배분하는 로직의 고도화 필요.
- **Attribution 분석 도구**: 축적된 `source_tab` 데이터를 기반으로 탭별 성과를 시각화하는 대시보드 기능 검토.
