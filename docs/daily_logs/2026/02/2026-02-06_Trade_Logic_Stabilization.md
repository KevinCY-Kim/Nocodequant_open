# 작업 일지 (2026-02-06) - 트레이딩 엔진 안정화 및 UI 고도화

## 1. 개요
오늘은 NoCodeQuant 시스템의 실전 운용 안정성을 확보하기 위해 발생 빈도가 높았던 UI 크래시와 중복 매매 이슈를 근본적으로 해결하고, 사용자 편의 기능을 대폭 강화했습니다.

## 2. 주요 작업 내용

### 2.1 QPainter "Active Painter" 오류 근절
- **문제**: 멀티스레드 환경에서 UI 갱신 시 `QPainter`가 중첩되어 작동하며 "Active Painter" 경고 및 크래시 발생.
- **해결**: 모든 `paintEvent`에 `try...finally`와 `painter.end()`를 적용하여 화가(Painter)의 생명주기를 강제 관리. 리스트 스냅샷(`list(self.data)`)을 활용하여 이터레이션 중 데이터 변경으로 인한 런타임 오류 차단.

### 2.2 레이아웃 과팽창 및 찌그러짐 원천 해결
- **문제**: 의사결정 허브 레이아웃이 데이터 양에 따라 유동적으로 변하며 레이턴시 및 가독성 저하 유발.
- **해결**: 의사결정 박스를 1줄 압축(`[Score] [Trend] [Decision]`)으로 변경하고, AI 추론 요약창의 높이를 6줄로 고정하여 시각적 불변성(Visual Invariance) 확보.

### 2.3 엔진 정지(PAUSED) 중 분석 유연성 확보
- **문제**: 엔진 정지 시 주문뿐만 아니라 차트 분석 및 종목 연동까지 중단되는 현상.
- **해결**: `process_market_data` 진입부의 차단 로직을 제거하고 주문 전송 직전에만 `engine_enabled`를 체크하도록 변경. 엔진을 꺼둔 상태에서도 상시 분석이 가능한 '보초병 모드' 구현.

### 2.4 중복 매매(Spam Order) 오류 근절 (Stamp Logic)
- **문제**: 매 티크마다 전략을 체크하는 과정에서 동일 봉(Candle) 내에서 동일 신호에 대해 수십 번의 주문이 나가는 현상 발생.
- **해결**:
    - **방향별 박제**: `(종목, 방향)`별로 마지막 주문 타임스탬프를 기록하여 동일 봉 내 중복 주문 차단.
    - **포지션 정합성**: 매수 시 잔고 0, 매도 시 잔고 존재 원칙을 물리적 가드로 추가.
    - **타임스탬프 비교**: `signal_ts <= handled_ts` 조건을 도입하여 지연된 데이터에 의한 오작동 방지.

### 2.5 초기화 크래시 및 사용자 편의성
- **문제**: 위젯 생성 전 기본값 설정 시 `AttributeError` 발생.
- **해결**: `apply_initial_defaults` 메서드를 도입하여 UI 로드 완료 후 안전하게 기본값(15분봉, 전문 스캘퍼) 적용.

### 2.6 20시 시간외 거래(ATS/Nextrade) 지원 확장
- **문제**: 정규장(15:30) 이후 시세 중단 및 ATS 패킷 수신 누락.
- **해결**: `KiwoomEngine`에 ATS 전용 화면번호(4000) 및 범용 체결 필터를 적용하여 20시까지 발생하는 모든 실시간 틱을 포착.

### 2.7 차트 인터랙션 및 툴팁 복구
- **변경**: 마우스 호버 시 가격 정보 즉각 표시 기능 복원 및 타임프레임 변경 시의 `UnboundLocalError` 해결. 900개 이상의 봉 데이터에서도 정확한 좌표 매칭 구현.

### 2.8 멀티세션 대시보드 실시간 동기화
- **해결**: `StateManager`로부터 정보를 가져와 300ms 주기로 보유 잔고 및 백그라운드 감시(보초병) 테이블을 강제 갱신. 실시간 수익률 변동 가시성 확보.
