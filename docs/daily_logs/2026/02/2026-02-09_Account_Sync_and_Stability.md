# 작업 일지 (2026-02-09) - 계좌 동기화 무결성 및 매매 안정성 확보

## 1. 개요
오늘 작업은 플랫폼의 내부 상태(StateManager)와 키움증권 서버 데이터 간의 불일치를 해소하고, 실전 매매 상황에서 발생할 수 있는 이상 작동(주문 스팸 등)을 원천 차단하는 '안정성 플랫폼화'에 집중했습니다.

## 2. 주요 작업 내용

### 2.1 실시간 계좌 잔고-포지션 동기화 (v13.3-Sync)
- **문제**: 프로그램 재실행 시 기존 포지션 정보를 불러오지 못하거나, 체결 후 잔고 반영이 지연되는 현상.
- **해결**: 
    - `opw00018`(계좌평가잔고내역) TR을 연동하여 로그인 및 주기적(60초)으로 전체 잔고를 절대값 동기화.
    - `OnReceiveChejanData`(실시간 체결) 수신 시 즉시 잔고 조회를 트리거하여 데이터 시차(Lag) 제거.

### 2.2 동기화 데이터 정합성 보강 (v13.3-DeepProbe)
- **문제**: 특정 환경(모의투자 등)에서 평단가가 0으로 표시되거나, 필드 밀림 현상으로 인해 손익이 터무니없이 높게 계산되는 오류 발생.
- **해결**:
    - **레코드명 명시**: `GetCommData` 호출 시 `"계좌평가잔고내역"` 레코드를 명시적으로 지정하여 데이터 혼선 차단.
    - **서버 원천 데이터 활용**: 로컬 계산 방식에서 벗어나 서버가 제공하는 `평가손익`, `수익률(%)` 필드를 직접 추출하여 HTS와 100% 일치하는 수치 구현.
    - **UI 가드**: 평단가가 0인 예외 상황에서 잘못된 수치가 노출되지 않도록 화면 표시 방어 로직 강화.

### 2.3 매매 루프 스팸 방지: 주문 보호막 (v13.4-Safety)
- **문제**: 실전 모드에서 매 신호마다 중복 주문이 전송되어 "과도한 주문" 메시지와 함께 계좌가 제한되는 리스크 확인.
- **해결 (Order Shield)**:
    - **Pending Guard**: 주문 송신 후 체결 확인 전까지 해당 종목의 추가 주문을 원천 차단.
    - **5초 쿨다운**: 동일 종목에 대해 최소 5초의 주문 간격을 강제.
    - **Inventory Check**: 매도 신호 시 실제 잔고 유무를 내부적으로 선제 확인하여 유효하지 않은 주문 차단.

### 2.4 HTS 방식의 차트 인터랙션 고도화 (v13.3-Interact)
- **기능**: 차트 위 마우스 휠 조작 시 메인 스레드 스크롤 간격을 유지한 채, 봉 갯수를 조절(줌 인/아웃)하는 HTS식 인터페이스 구현.
- **개선**: 최대 표시 봉 갯수를 500개로 확장하고, 휠 이벤트 버블링을 차단하여 조작감을 개선함.
