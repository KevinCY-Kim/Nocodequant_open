## 2. 작업 수행 내역 (Accomplishments)

### 2.1 [L3] 실행 엔진(ExecutionManager) 및 파라미터 인프라 안정화
- **하드코딩 차단 제거**: `execution_manager.py` 내부에 존재하던 `score < 60` 하드코딩 필터를 제거하고, 국면별 설정값과 연동되도록 수정함.
- **국면 동기화**: `UPTREND`, `DOWNTREND` 국면을 명시적으로 추가하여 `config_engine`의 설정이 누락 없이 반영되도록 함.
- **파라미터 전면 완화 (V21.7 TEMP)**: 데이터 수집 극대화를 위해 진입 임계치(`ENTRY_THRESHOLD` 등)를 50~58 수준으로 하향하고, `VOL_RATIO_WARN`을 1.5로 완화함.
- **안정성 가드 롤백**: 데이터 수집 우선 원칙에 따라, 신호 발생을 억제할 수 있는 500ms 캐시 방어막 및 로거 복원 코드를 사용자의 요청에 따라 롤백함.

### 2.2 [L3] 4단계 포렌식 진단 로그 주입
- 전송 파이프라인의 병목을 추적하기 위한 실시간 로그 4종을 `execution_manager.py`에 주입함.
    - `[BUY_PASS1]`: 점수 및 허들 통과 확인
    - `[BUY_COOLDOWN]`: 60초 쿨다운 가드 작동 확인
    - `[BUY_POLICY_BLOCK]`: 리스크 정책(PolicyEngine) 차단 확인
    - `[BUY_MME_BLOCK]`: 자금 관리 엔진(MME) 수량 0 처리 확인

### 2.3 [L3] 최소 기능 섀도우 모드 (MVSM) 구축
- **Bypass Logic**: 가드 위반 시에도 실제 주문(BUY)을 수행하되, `[SHADOW]` 태그를 붙여 기록만 남기는 모드를 도입함.
- **Toggle Switch**: `config_engine.py`를 통해 전역 섀도우 모드 ON/OFF 제어권 확보.
- **File Logging**: 가드를 위반하며 진입한 종목의 데이터를 `logs/shadow_guard_log.jsonl` 파일에 JSONL 형식으로 자동 누적 기록함.
