# NCQ 데일리 작업 로그 (2026-04-23)

## 📋 요약 (Summary)
오늘의 핵심 과업은 전략 성과보드에서 발생하는 **"동일 종목의 중복 거래 기록(GTID 파편화)"** 현상을 완전히 해결하고 데이터 무결성을 확보하는 것이었습니다. 분석 결과, 분할 매도 체결 시 각기 다른 GTID가 생성되거나 전략 엔진의 신호 중복 발송으로 인해 `fill_accumulator`가 분리되는 현상이 확인되었습니다. 이를 해결하기 위해 **매도 누적기(SELL Accumulator)의 무조건적 재활용 로직**을 도입하고, DB 집계 시 `order_id`와 `gtid`를 통합 관리하는 **Fallback 파이프라인**을 강화했습니다. 또한 문자열 `"None"`이 ID로 오인되어 데이터가 꼬이는 엣지 케이스까지 차단하여 제도권 수준의 데이터 정합성을 달성했습니다.

## 🛠 주요 변경 및 개선 사항

### 1. **[Order] 매도 거래 통합 및 누적기 재활용 로직 강화 (V20.9.5)**
- **SELL Accumulator 상시 재활용**: 
    - 기존에 `parent_gtid`가 `GTID_UNKNOWN`일 때만 작동하던 재활용 로직을 `side == "SELL"`인 경우 상시 작동하도록 확장.
    - 이를 통해 전략 엔진이 여러 번의 SELL 신호를 보내더라도 동일 종목의 매도는 항상 하나의 `stable_gtid`로 수렴되어 DB에 단일 행으로 기록됨.
- **주문 식별자(order_id) 추출 로직 고도화**:
    - `FILL` 이벤트 발행 시 `order_id` -> `fill_id` -> `parent_gtid` -> `stable_gtid` 순으로 Fallback을 적용하여 `order_id`가 NULL이 되는 상황을 원천 차단.
    - 강제 플러시(`flush_sell_accumulators`) 시에도 빈 문자열 대신 `stable_gtid`를 주입하여 집계 정합성 확보.

### 2. **[Persistence] 데이터 집계 무결성 및 UI 정합성 패치 (V20.9.5)**
- **SQL 집계 쿼리 최적화**:
    - `get_recent_trades`의 총 건수 계산 방식을 `COUNT(*)`에서 `COUNT(DISTINCT COALESCE(order_id, gtid))`로 변경.
    - UI 테이블의 `GROUP BY` 결과와 상태바의 총 건수를 완벽히 일치시켜 사용자 혼란 제거.
- **데이터 오염 방지(Sanitization)**:
    - 직렬화 과정에서 발생할 수 있는 문자열 `"None"`이 유효한 ID로 평가되는 버그를 수정.
    - `OrderManager`와 `PersistenceManager` 양측에서 `"None"` 문자열 필터링을 강화하여 엉뚱한 거래들이 하나의 그룹으로 묶이는 현상 방지.

### 3. **[UI] 거래 로그 가독성 및 신뢰도 향상**
- **식별자 표시 로직 개선**:
    - 주문번호가 없을 경우 GTID를 대신 표시하되, 툴팁을 통해 상세 GTID 정보를 제공함으로써 투명성 확보.
    - 분할 체결된 거래들이 하나의 행으로 합산(수량, 수익금)되어 표시됨을 검증 완료.
