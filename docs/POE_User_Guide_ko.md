# Profit Optimization Engine (POE v27.0) 사용 가이드

> **"수익은 예측이 아니라 최적화의 결과입니다."**
> POE(Profit Optimization Engine)는 NoCodeQuant의 전략 실행력을 극대화하기 위한 자가 진단 및 구조적 관측 시스템입니다.

---

## 1. POE의 핵심 철학 (The Core Logic)

기존의 전략이 단순히 "신호가 오면 산다"에 집중했다면, POE v27.0은 **"지금 내 전략이 시장 환경(Regime)에 적합하게 동작하고 있는가?"**를 실시간으로 감시하고 튜닝합니다.

### 주요 3대 메커니즘:
1.  **구조적 관측 (Observability)**: 시스템의 심장 박동(Heartbeat)과 상태 전이(FSM)를 초단위로 기록하여 사후 분석을 가능케 합니다.
2.  **고밀도 검증 (Heartbeat Test)**: 극단적인 변동성 환경을 시뮬레이션하기 위해 강제로 '1분봉' 고속 가속 모드로 전환하여 로직의 극한을 테스트합니다.
3.  **자가 튜닝 (Auto-Tuning)**: 누적된 매매 결과와 손익 곡선을 기반으로, 현재 시장에 가장 적합한 지표 임계값을 AI가 역산하여 제안합니다.
4.  **자율 통치 (Self-Governing)**: 정책을 단순히 제안하는 것을 넘어, 시장 레짐이 정책 수립 시점과 다를 경우 실시간으로 리스크를 강제 집행(Clamp)하여 시스템을 보호합니다.
5.  **라이프사이클 통합 [V27.0]**: `EngineLifecycleManager` 및 Coordinated Shutdown과 연동되어 셧다운 시 미완료 누적기를 안전하게 플러시하고 포렌식 버퍼를 백업합니다.

## 2. 주요 기능 상세 설명

### A. 구조적 관측 (Observability) 활성
- **기능**: 전략 연산의 중간 과정, 지표 간의 충돌 발생 여부, FSM(유한 상태 머신)의 전환 로그를 실시간으로 저장합니다.
- **활용**: 매매 결과가 예상과 다를 때 `forensic_log`를 확인하여 로직의 '누수' 지점을 찾을 수 있습니다.
- **권장**: 상시 활성화를 권장합니다.

### B. 1분봉 고밀도 하트비트 테스트
- **기능**: 클릭 시 현재 설정을 유지한 채 타임프레임을 즉시 **1분봉**으로 강제 고정합니다.
- **목적**: 5분/15분봉 전략이 1분봉의 빠른 노이즈 환경에서도 안정적으로 동작하는지, 주문 집행 지연(Slippage)이 발생하는지 단기간에 테스트할 때 사용합니다.
- **주의**: 변동성이 극심한 구간에서 활성화 시 잦은 신호가 발생할 수 있습니다.

### D. Institutional Overfitting Guard
- **기능**: 자가 튜닝 결과의 통계적 신뢰도(`Weight`)가 사용자가 설정한 `진입 신뢰도 임계값` 미만일 경우, 정책 저장을 원천 차단합니다.
- **목적**: 데이터 밀도가 낮은 구간에서 발생하는 과적합(Overfitting) 정책이 실전에 투입되는 것을 방지하는 최종 안전 장치입니다.

### E. 실시간 자율 통치 가드 (Self-Governing Guard)
- **Regime Drift Guard**: 현재 실시간 시장 레짐이 정책이 활성화된 시점의 레짐과 일치하는지 감시합니다.
- **Runtime Risk Clamp**: 레짐 불일치 및 신뢰도 저하로 인한 `Drift Score`가 0.7을 초과할 경우, `MIN_CONFIDENCE`를 35%로 자동 상향하여 저품질 신호 진입을 즉각 차단합니다.
- **Audit Trail**: 정책 저장 시 이전 10개의 정책 이력을 자동으로 보관하여 사고 발생 시 완벽한 소급 분석을 지원합니다.

## 3. 실전 POE 활용 시나리오

### 시나리오 1: "수익은 나는데 찝찝할 때"
1. `구조적 관측`을 켠 상태로 1시간 운용합니다.
2. `Expected Edge` 수치를 확인합니다.
3. 수치가 점점 낮아진다면 현재 시장이 전략에 불리해 지고 있다는 신호이므로 `자동 튜닝`을 실행하여 임계값을 상향 조정합니다.

### 시나리오 2: "새로운 로직을 빨리 검증하고 싶을 때"
1. 전략 프리셋을 설정하고 `1분봉 고밀도 하트비트 테스트`를 활성화합니다.
2. 5~10분 내에 발생하는 잦은 신호들을 통해 진입/청산 타점이 의도대로 동작하는지 육안으로 확인합니다.
3. 검증이 완료되면 체크를 해제하여 원래의 호흡(예: 15분봉)으로 돌아옵니다.

## 4. POE 상태 지표 읽는 법

| 지표명 | 의미 | 적정 범위 |
| :--- | :--- | :--- |
| **상태** | 현재 관측 엔진의 동작 여부 | `관측 중` 또는 `튜닝 중` |
| **False Break Rate** | 돌파 신호 중 가짜였던 비율 | **20% 미만** (낮을수록 우수) |
| **Expected Edge** | 신호당 기댓값 (수익/비용) | **양수(+) 유지 필수** |

## 5. FAQ

**Q: POE를 켜면 PC가 느려지나요?**  
A: 비동기(Async) 루프에서 동작하므로 메인 UI 성능에는 영향이 거의 없습니다. 다만 고밀도 하트비트 모드에서는 로그 파일 크기가 빠르게 증가할 수 있습니다.

**Q: 자동 튜닝된 값은 자동으로 저장되나요?**  
A: 보안 및 책임 매매 원칙에 따라 AI의 권장값은 **먼저 리포트로 제시**됩니다. 사용자가 내용을 확인하고 `실시간 조건 적용` 버튼을 눌러 승인해야 최종 반영됩니다.
